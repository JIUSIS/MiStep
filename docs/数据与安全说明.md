# 数据与安全说明

## 应用运行时

Mi Step 在系统框架和 SystemUI 作用域中工作，通过系统任务信息维护主副区域、焦点和输入映射。剪贴板、常用应用和媒体信息用于对应功能。代码中的 Binder token、任务 ID、系统私有目录及输入库特征是运行时接口或测试数据，不是本机账号凭据。

已有媒体信息没有歌词时，歌词查询可能将歌曲名、歌手、时长或曲目 ID 发往对应服务，包括网易云音乐、酷狗、汽水音乐和 LRCLIB。结果取决于网络与曲库。本项目没有为这些请求内置个人账号、Cookie 或 API 密钥；当前版本不需要注入播放器进程。

系统和模块日志可能包含应用包名、任务状态和错误信息。反馈问题前应先检查并删去个人内容，不要直接上传整份设备日志或截图。

## 本次源码发布范围

源码以独立目录重新整理，没有携带原工作区的 Git 历史。提交前按实际待上传清单检查：

- 私钥、keystore、证书容器、账号凭据、令牌与带密码配置。
- 本机绝对路径、设备序列号、局域网地址和设备采集记录。
- APK、数据库、运行日志、截图录像、ROM、反编译文件和历史实验缓存。
- 图标及编译期依赖中的多余元数据；发行 APK 的文件目录与可读字符串。

`build/`、`dist/`、本机配置和常见敏感文件扩展名均在 `.gitignore` 中。发行 APK 与校验文件通过 Release 附件发布，源码归档按允许清单生成。忽略规则是辅助措施，不能代替每次发布前检查暂存内容。

## 后续维护

签名材料和凭据始终放在仓库外。发现疑似敏感信息时，先停止继续发布、核对历史与附件的影响范围，并撤销或更换已泄漏的凭据；不在公开 Issue 中粘贴原值。把仓库改回私有或删除当前文件，不能撤回已经被复制的内容。

分发衍生版本时的源码义务见 [许可说明](许可说明.md)。签名私钥、密码、
个人数据和设备日志不属于需要交付的源码；提交署名邮箱则属于 Git 历史
元数据，应在提交前决定是否使用 GitHub 的 `noreply` 地址。
