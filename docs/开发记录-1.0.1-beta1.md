## 顶部窗口

- 顶部区域双指平行上下滑动，按长方体相邻面翻滚；fix1起每次手势限制相邻一个面，松手吸附，剔除背向面。控制区音乐之后的第三页也可打开。下方主区域和三副格位置保持。
- 无底部提示条或原标题长按。窗口使用顶部实际剩余矩形，界面与触摸按同一比例缩放。TOP按用户最新选择使用242dpi，Task及Activity资源尺寸与逻辑视口一致；归还清除覆盖，恢复系统原资源密度。11T同1630×939视口对应1078×621dp/sw621，应用可能据此选择平板资源。
- 空位复用三副格的壁纸背景和加号。先在主屏打开应用，再点顶部加号收进同一任务；手动添加允许当前竖屏页。应用在顶部换页、返回或请求竖屏时继续保留，不只承载一个视频页面。单指直接操作应用，只有识别顶部双指平行竖直手势后才接管触摸。
- 横屏窗口只在手动点击空位后收纳主屏应用；应用横屏请求不自动打开或接管，旧自动设置不再读取。主屏→横屏窗口与横屏窗口→主屏均向中心收起，再从目标中心展开；三副格交换与顶部控制翻页保留原动画。
- 接入后默认焦点回主区域；空顶部不接管主屏焦点。显式点击顶部内容后，允许应用获得原生焦点完成交互，不通过定时抢焦点维持优先级。收回、退出和锁屏继续沿用原任务归还链。

## Upper task window

Swipe up or down with two fingers inside the top strip to roll between the control and task faces. Since fix1, each gesture is limited to one adjacent face and back-facing surfaces are culled. The third control page also opens the task face. There is no bottom hint bar. The window uses the actual remaining rectangle and scales the interface and input together. The top task uses the selected 242dpi configuration; both Task and Activity metrics follow its logical viewport. Handback clears the overrides and restores native resources.

Build 1000012/fix3 passed the full build and offline suite, including 28 production Activity configuration checks. On 11T, a real portrait video in Douyin Lite fit the top viewport and handback restored 440dpi. Hongguo’s comment panel displayed fully; dismissal restored the video window focus, pause worked, and the saved window state confirmed navigation back to the main activity. The user’s repeated jumping was not reliably reproduced on either build, so this bounded result does not establish a complete fix. The 17PM app and occasional main-area landscape clipping remain unverified.

The empty face shares the side cells’ wallpaper and plus button. Open an app in the main area, then tap the top plus to collect the same task. Manual collection accepts its current portrait page, and navigation or a portrait request keeps the app in the top window. Admission is manual only; orientation changes never open the top face or collect a task. Transfers between the main area and the top window collapse into the source center, then expand from the destination center in both directions. This animation is specific to those transfers. Default focus favors the main area; explicit touches can focus the top app for normal interaction.

Build 1000010 increases the top interface size after feedback that text and buttons were too small. It uses sqrt(fit) instead of full-display fit, keeping a uniform projection and native app resources. On the same 1080×622 top rectangle, the dynamic viewport is now 1630×939, scale about 0.663 and effective density about 292dpi. The measured 48dp square increased from approximately 58px to 87px high. A bounded 11T test passed same-task navigation, original-activity handback, unchanged main-area control bounds and normal Home exit. Temporary tools were removed. Actual third-party app readability still needs user feedback.

The earlier build 1000009 was installed and normally rebooted on the 11T test device. A bounded test covered empty-slot collection, a second activity within the same task, navigation back, handback of the original activity instance and normal Home exit. Real dp/sp controls returned to their original main-area dimensions. The native density stayed at 440dpi throughout; the tested top rectangle was 1080×622, projected from a dynamic 2460×1417 viewport at scale 0.439. Temporary test tools were removed. This does not establish compatibility with every app, game, clone profile or device. Build 1000008’s direct density changes caused a user-reported partial scaling residue in a video app; that app still needs independent validation with the revised approach.
