# 作用域与系统适配

推荐作用域包括系统框架、SystemUI，以及仅承载模块设置入口的系统设置。普通应用换包、升级或切换内容，不应成为追加LSPosed作用域的理由。

| 入口 | 职责 | 当前边界 |
| --- | --- | --- |
| 系统框架 `android` | 任务与窗口配置、主区Surface缩放、InputDispatcher坐标、主副交换恢复、输入法进程配置 | 在系统端统一处理，不注入普通应用的View、MotionEvent或DisplayMetrics |
| 系统界面 `com.android.systemui` | 顶部/副任务宿主、手势、原生面板与控件、Shell过渡 | 宿主按物理屏幕布局；属于主区的原生面板沿主区窗口与旋转链路运行 |
| 设置 `com.android.settings` | 系统设置首页的原生Mi Step条目 | 只向Header列表添加模块入口并处理其点击，不修改普通应用布局或输入 |
| 小米输入法 `com.xiaomi.type`，可选 | 仅阻止横屏时自动切换悬浮模式 | 仍依赖输入法内部方法，尚未迁移到系统端；不使用此功能时无需选择 |

设置作用域已按最新产品要求恢复，仅注入原生设置入口；无独立桌面图标。标准抖音TOP图片容器补丁及其宿主授权发布已撤回。旧AppRawInputHook没有调用入口，已从产品源码移出；当前主区raw坐标继续由system_server统一处理。播放器歌词、扫码和已有应用快捷方式也不需要给相应应用追加作用域。

本次改的是推荐元数据和模块入口，不替用户修改LSPosed中保存的勾选。设置只进入独立的入口钩子；抖音和其它普通应用入口直接返回。已安装旧构建的行为要等实际加载新构建后才改变。

## 框架与SystemUI的调整原则

1. **统一窗口几何。** 任务bounds、Activity的appBounds/maxBounds、窗口frame、insets和最终Surface变换使用同一逻辑视口。TOP与主区有不同视口，但通过任务身份与所有权区分，不通过应用包名推测布局。
2. **输入只补偿一次。** 系统发布端负责主区raw映射，普通local和多指样本保留原生语义。原生浮窗、TOP和物理宿主各走已确认的窗口角色门禁，避免再次在应用里反向缩放。
3. **SystemUI区分窗口职责。** MiStep顶部、侧区和应用选择框采用物理窗口上下文；通知、控制中心等主区原生面板与其输入、方向和资源配置保持一致。不能把整个SystemUI无差别地当作宿主或主应用。
4. **过渡与恢复沿同一所有权链。** Shell动画重建父节点、旋转或原生浮窗出现时，核真实parent/leash、净缩放和触区。退出时恢复原窗口、配置与输入；不注册替代全局organizer。

这些原则用于约束后续系统改动。本轮没有证据支持重写所有应用的屏幕尺寸或强制图片裁切，因此没有加入此类全局补丁。

## 后续顺序与验证边界

先继续核主区原生系统面板和MiStep物理宿主在进入、旋转、退出时的配置及触区，再核输入法可选策略是否能通过统一的系统窗口信息替代。只有确认等效后，才能移除小米输入法的最后一项应用内部兼容逻辑。

“部分图文展开评论错位”按用户要求暂停。正常全屏对照尚未进行；本轮撤回应用补丁不等于该问题已修复。编译与离线回归、实际安装加载、真实画面/触摸/退出恢复分别记录，不互相替代。
