这是自定义软件许可，标识为 `LicenseRef-MiStep-NC-SA-1.0`。

作者希望大家可以学习、改进和免费分享，同时防止把项目套壳、换名后
出售，或者拿走源码做成闭源收费版本。因此，本项目采用 **源码公开
（Source Available）** 的方式分享；由于限制商业化，不称为 OSI 定义
下的开源软件，也不把它标成 GPL、AGPL 或 CC BY-NC-SA。

| 发布自己改进的免费版本 | 可以，公开完整对应源码、说明修改并沿用同一许可 |

## 分发改版时怎么提供源码

1. 保留 `LICENSE`、原作者和已有贡献者的署名，以及第三方许可。
2. 发布与安装包实际对应的完整源码、资源、构建脚本和依赖说明，
   清楚标明修改；只给旧版本、混淆代码或缺少基线的补丁不符合要求。
3. 在下载页面或应用内提供公开、免费、无须审批的源码获取地址。
   分发期间保持该公开地址可用；停止分发后仍须保持不少于三年，
   或在分发时与每份副本一并交付完整源码归档。后一做法替代停止
   分发后的保留义务，不免除分发期间公开源码地址的要求。
4. 对受本许可覆盖的衍生内容沿用本许可 1.0，不增加保密或闭源限制。

**公开源码不等于公开私钥。** 不要提交签名密钥、密码、个人数据或
设备日志；通用工具与第三方组件依照各自许可提供或注明获取方法。

## 为什么不是 GPL-3.0

GPL-3.0 允许商业使用和收费分发，要求在分发受其覆盖的程序时向接收者
提供对应源码，但不要求所有源码都发布在公共 GitHub 仓库。它无法满足
作者这次提出的“禁止套壳商业化”要求。

CC BY-NC-SA 也不能直接替代本软件许可：ShareAlike 本身没有软件对应
源码的交付要求，Creative Commons 官方也不建议用 CC 许可管理软件。

官方参考：[OSI 开源定义](https://opensource.org/osd)、
[GNU GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html)、
[Creative Commons 软件许可 FAQ](https://creativecommons.org/faq/#can-i-apply-a-creative-commons-license-to-software)。
